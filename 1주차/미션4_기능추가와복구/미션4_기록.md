## 원본과 달라진 곳 (영화_원본.html → 영화_기능추가.html)

"원래 기능은 바꾸지 마"를 지켰는지 줄 단위로 비교했습니다. 바뀐 곳은 두 군데뿐이고, 옮기기(`move`), 카드(`card`), 끌어 놓기(`wireDrop`), 추가, 처음으로, 저장(`save`) 코드는 그대로입니다.

| 위치 | 바뀐 내용 |
|---|---|
| CSS `.label`, `.pool-head`, `.count` | 등급 글자 아래에 숫자가 오도록 세로 배치, 미분류 제목 옆에 숫자 배치 |
| `render()` 함수 | 등급 칸마다 `state.items.filter(item => item.tier === tier).length`로 개수를 세어 글자 아래에 표시, 미분류 제목에도 같은 방식으로 개수 표시 |

숫자를 따로 저장하지 않고 화면을 다시 그릴 때마다 영화 목록에서 세기 때문에, 옮기기·추가·처음으로·새로고침 뒤에도 숫자가 실제 배치와 같았습니다(4단계 표).

### 문제가 생겼다면 따랐을 절차 (멈춤 규칙)

이번에는 1번 확인에서 문제가 나오지 않아 2~4번까지 가지 않았습니다.

1. 받은 파일을 원래 기준 7개와 새 기준 5개로 처음부터 확인한다.
2. **새 기능만 틀리면**: 본 대로(행동 → 기대 → 실제) Gemini에게 말해 고쳐 달라고 하고, 받은 파일은 `영화_기능추가_수정1.html`, `…_수정2.html`처럼 새 이름으로 저장해 1번부터 다시 확인한다.
3. **원래 기능(옮기기·추가·저장·처음으로) 중 하나라도 망가지면**: 그 파일을 더 고쳐 달라고 하지 않고 수정 요청을 멈춘다.
4. `영화_원본.html`과 `기획서.md`를 다시 첨부해 Gemini **새 대화**에서 처음 요청 문장으로 다시 요청하고, 받은 파일을 새 이름으로 저장해 1번부터 다시 확인한다. 망가진 파일도 지우지 않고 남겨 기록에 적는다.
