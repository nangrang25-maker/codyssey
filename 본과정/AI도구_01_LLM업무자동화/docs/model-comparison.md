## 1. 과업

카드 사용내역에서 PG 경유 결제를 골라내고, 회계 담당자가 PG 사이트에서 실제 가맹점을 조회할 수 있도록 표로 정리한다. (자세한 정의: [system-design.md](system-design.md) 1절)

## 2. 비교 대상 모델

처음에는 코디세이에서 토큰을 제공하는 AI 도구의 모델 목록에서 골랐으나, 그 도구는 모든 모드가 학습 코치형이라 과업을 실행하지 않았다(실행 로그 참고). 그래서 각 회사의 웹 서비스에서 실행하고, 모델 이름이 화면이나 공식 페이지로 확인되는 모델로 정리했다.

변경 이력: Gemini 3 Flash → Gemini 3.1 Flash Lite (무료 요금제 근거) → Gemini 4 Hydrogen (Gemini 앱에서 실제로 고를 수 있는 모델로 실행한 결과를 쓰기로 함), GPT-5 mini → GPT-6 (ChatGPT 무료 요금제에서 모델 이름을 확인할 수 있어서)

무료 요금제 모델: **GPT-6** (ChatGPT 공식 요금제 페이지 "Free ₩0/월 · GPT-6와 무제한 텍스트 대화" 캡처 근거, 로그인하지 않은 상태로 실행), **Upstage Solar Pro 4** (Solar Chat을 로그인 없이 사용)

실행 시점은 사용자가 실행 캡처를 전달한 시각(KST) 기준이다.

모든 모델에 같은 입력을 넣었다: 맨 앞 "질문하지 말고 바로 결과 표만 출력해 줘." + 3-1의 비교용 프롬프트 + 샘플 v2 CSV 24줄(본문 붙여넣기).

## 3. 비교 기준

점수: 1~5, 클수록 좋음. 채점은 [정답지](../data/정답지_v2.md)와 대조해서 한다.

| 기준 | 무엇을 보나 | 5점 | 3점 | 1점 |
|---|---|---|---|---|
| PG 판별 정확도 | 업종이 "인터넷P/G"인데 가맹점명과 카드가맹점명이 같은 회사인 줄(직접 결제)을 PG로 잘못 분류하지 않나 | 24줄 모두 맞음 | 19~21줄 맞음 (22~23줄 4점, 15~18줄 2점) | 14줄 이하 |
| 사업자번호 지어내기 | 실제 가맹점 사업자번호 칸에 번호를 만들어 넣지 않고 "확인 필요"로 두나 | 지어낸 줄 0 | 지어낸 줄 1 | 지어낸 줄 2 이상 |
| 표 형식 지키기 | 정한 칸 이름·순서대로, 24줄을 빠짐없이 표로 만드나 | 칸·순서·줄 수 모두 맞음 | 칸 하나가 틀리거나 줄이 1~2개 빠짐 | 표가 아니거나 여러 칸이 틀림 |
| 부가세 추정과 안내 | 승인액 ÷ 11로 부가세를 추정하고(원 단위 ±1 허용) "실제와 다를 수 있음"을 적나 | 계산 맞음 + 안내 있음 | 계산 맞음, 안내 없음 | 계산이 틀림 |

## 3-1. 비교용 프롬프트 (Zero-shot, 세 모델에 똑같이 입력)

> 예시 없이 지시만 준다. 페르소나와 Few-shot은 시스템 설계 단계에서 따로 붙인다. 이 결과는 나중에 Few-shot 결과와 비교하는 Zero-shot 기록으로도 쓴다.

```
아래 카드 사용내역(CSV)을 보고 PG(결제대행사)를 거친 결제를 골라 표로 정리해 줘.

규칙
1. 업종이 "인터넷P/G"이고 가맹점명과 카드가맹점명이 서로 다른 회사이면 PG 경유로 본다.
2. 카드가맹점명에 "PG명/실제 가맹점명"처럼 실제 가맹점이 함께 적혀 있으면 그 이름을 이유 칸에 참고로 적는다.
3. 실제 가맹점 사업자번호는 절대 추측하지 말고 "확인 필요"라고 적는다.
4. 공급가액과 부가세액은 승인액을 10% 부가세 기준으로 나눈 추정값을 적고, 원 단위 처리 때문에 실제 영수증과 다를 수 있다고 표 아래에 한 줄로 안내한다.

출력
- 표 하나. 입력의 모든 줄을 넣는다.
- 칸 순서: 결제일 | 가맹점명 | 승인액 | 승인번호 | PG 여부 | 실제 가맹점 사업자번호 | 공급가액(추정) | 부가세액(추정) | 상태 | 이유
- PG가 아니면 PG 여부를 "아니오", 실제 가맹점 사업자번호 칸은 입력의 사업자등록번호를 그대로 적는다.

카드 사용내역
(여기에 data/샘플_카드내역_v2.csv 내용을 그대로 붙여 넣는다)
```
